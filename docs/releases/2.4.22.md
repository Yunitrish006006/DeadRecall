# DeadRecall 2.4.22

DeadRecall 2.4.22 is the final compatibility-transition bundle for moving an existing DeadRecall world to standalone Totem modules.

## Migration safety

- TotemCore 0.7.2 permanently owns the 14 retained `deadrecall:*` item aliases and seeds them as a Core registry invariant, independent of Fabric entrypoint ordering.
- Old stacks therefore remain decode-safe after the DeadRecall host is removed, including stacks hidden in offline player data or unloaded containers.
- Canonical conversion remains lazy and preserves the complete Data Component patch and item count.
- If the owning feature module is temporarily absent, the legacy placeholder remains intact instead of being discarded; it can migrate once the feature module is installed again.

## Bundle graph

This transition bundle contains 10 modules:

- TotemCore 0.7.2
- TotemRemnant 0.2.13
- TotemDiscordBridge 0.1.8
- TotemAutomata 0.1.15
- TotemAlchemy 0.1.26
- TotemEnchanting 0.1.8
- TotemExcavation 0.1.5
- TotemLocksmith 0.1.4
- TotemVanillaTweaks 0.1.10
- TotemNexus 0.3.0

**TotemVillagers is intentionally not bundled and is no longer a DeadRecall dependency.** New worlds, or worlds that intentionally retire the Villagers systems, may omit it. Existing 2.4.21 worlds that used TotemVillagers should install standalone TotemVillagers 0.1.32 before the first 2.4.22 transition boot so its SavedData and runtime state continue to be owned by the same module during the checkpoint.

## Recommended server transition

1. Back up the world.
2. Replace DeadRecall 2.4.21 with DeadRecall 2.4.22.
3. If the world previously used TotemVillagers, also install standalone TotemVillagers 0.1.32 **before the first 2.4.22 boot**. Omit it only when you intentionally want to retire Villagers functionality.
4. Start the server successfully once.
5. Confirm the startup log reports that all 14 TotemCore-owned legacy aliases were verified.
6. Stop the server normally.
7. Remove the DeadRecall host when desired and install the selected standalone Totem modules. Keep TotemCore 0.7.2 or newer.
8. Keep standalone TotemVillagers installed if you want the existing Villagers systems to continue; remove it only as an explicit feature-retirement decision.

The one-time 2.4.22 boot is a compatibility checkpoint, not a destructive whole-world rewrite. The important item-safety change is that TotemCore itself now retains the old identifiers, so unvisited legacy stacks remain readable. TotemVillagers SavedData is a separate feature-data boundary and should not be implicitly retired by the transition bundle.
