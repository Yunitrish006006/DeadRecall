# DeadRecall 2.4.21

DeadRecall 2.4.21 moves the Totem-wide friendship service into TotemCore 0.7.0 and rebuilds the exact eleven-module compatibility bundle against the new Core minor. The outer DeadRecall JAR remains a migration-only compatibility host; gameplay remains owned by the nested Totem modules.

- TotemCore `0.7.0`
- TotemRemnant `0.2.13`
- TotemDiscordBridge `0.1.8`
- TotemAutomata `0.1.15`
- TotemAlchemy `0.1.26`
- TotemEnchanting `0.1.8`

- TotemNexus `0.3.0`

## Shared Friendship Migration

- TotemCore is now the canonical owner of friendships and pending invitations through `TotemFriendshipApi`.
- Existing worlds keep the historical `deadrecall:space_friends` SavedData identifier, so established friendships and pending invitations continue without requiring players to add each other again.
- TotemNexus keeps the friend UI, Space Unit visibility and teleport features, but no longer owns the social database.
- TotemLocksmith `FRIENDS` access now queries TotemCore directly and no longer requires TotemNexus to be installed.
- Standalone feature modules use the validated Core dependency range `>=0.7.0 <0.8.0`; CI still builds against the exact Core 0.7.0 merge commit.
- DeadRecall itself continues to pin exact module versions and retains its exact client/server module-version handshake.

## Included Gameplay Fixes Since 2.4.20

- TotemAutomata `0.1.15` retains the new heterogeneous Gathering Storage: multiple item/component types may share the configured total carry capacity, including mixed Hammer drops.
- TotemAlchemy `0.1.26` retains cauldron potion mixing, unfinished mixture bottles, effect opposition/dilution and the expanded manual.
- TotemExcavation `0.1.5` retains full Hammer selection reset after a successful area excavation.
- TotemLocksmith `0.1.4` retains the Access / Members / Keys management GUI and adds Core-native friendship authorization.
- TotemEnchanting `0.1.8` retains blocked-bookshelf enchanting-power regression protection.

## Validation

- All eleven standalone module repositories pass their own Core 0.7 compatibility gates before being pinned here.
- All eleven standalone module JARs are rebuilt from immutable merge commits.
- The final DeadRecall bundle must contain exactly eleven nested JARs with matching exact dependency metadata.
- The assembled bundle must start on a dedicated Fabric server and reach the normal `Done` state.
- Standalone/Modrinth metadata is validated in dry-run mode after regenerated JAR checksums are committed.
- Successful Bundle Smoke runs retain the verified `deadrecall-2.4.21-bundled.jar` and standalone module JARs as GitHub Actions artifacts.
