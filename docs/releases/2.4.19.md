# DeadRecall 2.4.19

DeadRecall 2.4.19 is a lockstep maintenance release for the village utility terrain-placement fix. The outer DeadRecall JAR remains a migration-only compatibility host; gameplay remains owned by the eleven nested Totem modules.

## Exact Versions

- TotemCore `0.6.0`
- TotemRemnant `0.2.11`
- TotemDiscordBridge `0.1.6`
- TotemAutomata `0.1.12`
- TotemAlchemy `0.1.23`
- TotemEnchanting `0.1.5`
- TotemExcavation `0.1.2`
- TotemLocksmith `0.1.0`
- TotemVanillaTweaks `0.1.8`
- TotemNexus `0.2.6`
- TotemVillagers `0.1.30`

## Village Utility Placement

- Generated village lumberyards and mines now use terrain-matching Jigsaw projection so their visible entrances and collision boxes resolve against local terrain instead of inheriting the remote town-centre elevation.
- Runtime registry and resource regressions lock both utility pools to `TERRAIN_MATCHING`.
- TotemVillagers was advanced from `0.1.29` to `0.1.30` so the corrected artifact does not reuse the already-recorded `0.1.29` release identity.

## Build Integrity

- DeadRecall CI now builds against the verified TotemCore `0.6.0` source commit instead of the obsolete `0.4.0` pin.
- CI explicitly verifies the Core and Villagers exact-version pins in both `build.gradle` and `fabric.mod.json` before building.
- The Modrinth release script runs in dry-run mode during CI and refuses version-number reuse when a remote release has a different SHA-512.
- The current-bundle pipeline rebuilds all eleven pinned standalone module JARs, validates their exact identities, assembles the nested DeadRecall bundle, and starts a dedicated Fabric server to the `Done` state before a live release is allowed.
