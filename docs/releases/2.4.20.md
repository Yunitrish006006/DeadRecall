# DeadRecall 2.4.20

DeadRecall 2.4.20 is the lockstep release that aligns the compatibility bundle with the current Totem module graph after the Core 0.6.1 transition and the module publishing hardening pass. The outer DeadRecall JAR remains a migration-only compatibility host; gameplay remains owned by the eleven nested Totem modules.

## Exact Versions

- TotemCore `0.6.1`
- TotemRemnant `0.2.12`
- TotemDiscordBridge `0.1.7`
- TotemAutomata `0.1.13`
- TotemAlchemy `0.1.24`
- TotemEnchanting `0.1.6`
- TotemExcavation `0.1.3`
- TotemLocksmith `0.1.1`
- TotemVanillaTweaks `0.1.9`
- TotemNexus `0.2.7`
- TotemVillagers `0.1.31`

## Lockstep Update

- Moves the entire bundled graph from TotemCore `0.6.0` to `0.6.1`.
- Includes the corrected TotemAlchemy `0.1.24` brewing/discovery release.
- Includes TotemVillagers `0.1.31`, TotemVanillaTweaks `0.1.9`, and TotemLocksmith `0.1.1` with corrected Core dependency metadata.
- Includes current Automata, Remnant, Discord Bridge, Nexus, Enchanting, and Excavation releases.
- Re-pins every source repository to an immutable commit so the bundled artifact can be reproduced and audited.

## Validation

- Build metadata must declare all eleven Totem dependencies as exact versions.
- All eleven standalone module JARs are rebuilt from the pinned source commits.
- The final DeadRecall bundle must contain exactly eleven nested JARs and matching exact dependency metadata.
- The assembled bundle is started on a dedicated Fabric server and must reach the normal `Done` state.
- Modrinth metadata is validated in dry-run mode before publication.
- Successful Bundle Smoke runs retain the verified `deadrecall-2.4.20-bundled.jar` as a GitHub Actions artifact.
